## Hallazgos críticos durante la auditoría

### Problema 1: Falsos positivos en CI por `=========` markdown
El primer commit del workflow CI tenía un patrón `^=======` que matcheaba subrayados markdown del INFORME_VERIFACTU.md y READMEs de `node_modules/`. Resuelto en 2 commits adicionales con regex estricto `^=======$` + `--exclude-dir=node_modules`.

### Problema 2: `redis.conf` con permisos 600 en cutover
El nuevo container `setex-prod-redis` no podía leer `redis.conf` (uid del container ≠ deploy). Cambiado a 644 (legible por todos los UIDs Docker). El antiguo ya estaba 644 — el `cp -av` mantenía el modo del original y se aplicó otra cosa en el chmod posterior.

### Problema 3: Traefik file provider apuntando al container viejo
`/docker/n8n/traefik-dynamic/setex.yml` (fichero estático fuera del repo) tenía `service: setex-frontend:80`. Tras cutover, ese hostname dejó de existir y Traefik devolvía 502. Fix: editado a `setex-prod-frontend:80`.

### Problema 4: `backup-postgres.sh` con container hardcoded
El script tenía `docker exec setex-postgres` literal. Tras cutover, el container es `setex-prod-postgres`. Actualizado a la nueva nomenclatura en el commit de migración de paths.

### Problema 5: GH plan Free no permite required reviewers
GitHub plan personal Free (no Pro) no soporta `required reviewers` en environments de repos privados. Workaround profesional: `workflow_dispatch` manual con input de confirmación textual `DESPLEGAR`. Mismo control efectivo, sin coste extra.

## Lecciones

1. **Cutover de bind mounts es más simple que volúmenes Docker** — `rsync` directo funciona porque los datos están en filesystem normal.
2. **Los scripts del proyecto necesitaban PATHS dinámicos** desde el principio — la lección para el roadmap es introducir un fichero `scripts/lib/paths.sh` con variables comunes (BASE_DIR, BACKUP_DIR, etc.) y todos los demás scripts lo source.
3. **Traefik file provider + Docker provider conviviendo** crea ambigüedad. Roadmap: eliminar el YAML estático y dejar todo el routing en labels Docker.

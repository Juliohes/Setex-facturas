# Cron jobs para SETEX staging
# Instalado en el crontab del HOST (no en contenedor). Por defecto, staging NO
# tiene crones activos — se activa cuando entramos en una ventana de validación
# (FASE 1B Etapa 5: 24-48h tras swap o cambios de develop).
#
# Aplicar (combina con el crontab activo del root, NO lo reemplaza):
#   sudo crontab -l > /tmp/cron-current
#   cat /opt/setex/staging/config/crontab.txt >> /tmp/cron-current
#   sudo crontab /tmp/cron-current
#   sudo crontab -l | grep setex/staging   # verificar
#
# Desactivar (al cerrar la ventana de validación):
#   sudo crontab -l | grep -v setex/staging | sudo crontab -
#
# Última actualización: 2026-04-27 23:00 UTC (FASE 1B Etapa 5 arrancada).

# ── Vigilancia ligera cada 30min ──────────────────────────────────────────
# Detecta containers no-healthy, errores backend recientes, smoke fallido,
# reinicios inesperados. Output silencioso si todo OK; alarma a stderr (mail
# automático del cron al user deploy) si hay fallo.
*/30 * * * * /opt/setex/staging/scripts/staging-watch.sh >> /opt/setex/staging/logs/staging-watch.log 2>&1

# ── Smoke HTTP cada hora (offset 17min para no chocar con fix-permissions) ──
# Verificación profunda de las 3 rutas críticas. Detecta regresiones que el
# watch ligero podría dejar pasar (timing windows, cache stale, etc.).
17 * * * * /opt/setex/staging/scripts/smoke-test-http.sh >> /opt/setex/staging/logs/smoke-http.log 2>&1
